## Dataset Extraction
The dataset extraction process involves retrieving images and their corresponding metadata from various sources. The extracted data is then processed and stored in a structured format for further analysis. The source code for this process is located in the `Dataset` directory. There are two main scripts for dataset extraction, namely `Extraction_Map.py` and `Extraction_StreetView.py`. The former is used for extracting data from Google Maps, while the latter is used for extracting data from Google Street View.

File Structure:
```
├── Dataset
|   ├── Input
|   |   ├──hdb_points_postal.csv --------- Input postal codes for dataset extraction
|   |   └── hdb_points.csv      ----------------- Input coordinates for dataset extraction
|   ├── Extraction_Map.py
|   ├── Extraction_StreetView.py
|   ├── Extraction_Satellite.py (Obsolete)
|   └── Update_Metadata.py
```
### Input Files
- `hdb_points_postal.csv`: This file contains the postal codes of the locations from which the images will be extracted. Each postal code corresponds to a specific location.
`hdb_points_postal.csv` follows the format:
```
id,postal_code,label
1,123456,Residential
2,234567,Others

where:
id: Unique identifier for each location.
postal_code: The postal code of the location.
label: Optional label for the location (e.g., Residential, Commercial, etc.).
```
- `hdb_points.csv`: This file contains the coordinates (latitude and longitude) of the locations from which the images will be extracted. Each coordinate corresponds to a specific location.
`hdb_points.csv` follows the format:
```
id,lat,lon,label
1,1.3521,103.8198,Residential
2,1.3522,103.8199,Others

where:
id: Unique identifier for each location.
lat: Latitude of the location.
lon: Longitude of the location.
label: Optional label for the location (e.g., Residential, Commercial, etc.).
```

### Extraction Scripts: Extraction_Map.py
This source code is responsible for extracting images using the Google Maps API. It takes the input CSV file containing postal codes or coordinates and retrieves the corresponding images and metadata. The extracted data is then saved in a structured format for further processing.

Important Note: The Google Maps API requires an API key for authentication. You can obtain an API key from the Google Cloud Console. Make sure to enable the necessary APIs (e.g., Maps Static API, Street View API) for your project.

#### Usage
Basic usage: (For more details, refer to the source code comments or type `python Dataset/Extraction_Map.py --help` for command-line options.)
```
python Dataset/Extraction_Map.py --input-file hdb_points.csv --output-dir ./extracted_images --api-key <YOUR_API_KEY>
```

The script accepts the following command-line arguments:
```
--input-csv: Path to input CSV file with location data (default: Dataset/Input/hdb_points_postal.csv)
--output-root: Root directory for output dataset (default: Dataset/Map)
--metadata-csv: Filename for combined metadata CSV (default: map_metadata.csv)
--api-key: Google Maps API key (default: from GOOGLE_MAPS_API_KEY env var)
--seed: Random seed for dataset splitting (default: 42)
--train-ratio: Proportion of samples for training set (default: 0.7)
--valid-ratio: Proportion of samples for validation set (default: 0.15)
--map-type: Google Map Tiles map type (satellite, roadmap, terrain; default: satellite)
--zoom-levels: Comma-separated zoom levels to download (default: 20)
```

The script will create a structured output directory containing the extracted images and a combined metadata CSV file. The metadata CSV will include information such as the location ID, postal code, coordinates, image URL, and other relevant details.

### Extraction Scripts: Extraction_StreetView.py
This source code is responsible for extracting images using the Google Street View API. It takes the input CSV file containing postal codes or coordinates and retrieves the corresponding images and metadata. The extracted data is then saved in a structured format for further processing.

Important Note: The Google Maps API requires an API key for authentication. You can obtain an API key from the Google Cloud Console. Make sure to enable the necessary APIs (e.g., Maps Static API, Street View API) for your project.

Basic usage: (For more details, refer to the source code comments or type `python Dataset/Extraction_StreetView.py --help` for command-line options.)
```
python Dataset/Extraction_StreetView.py --input-file hdb_points.csv --output-dir ./extracted_images --api-key <YOUR_API_KEY>
```

The script accepts the following command-line arguments:
```
--input-csv: Path to input CSV file with location samples.
--output-root: Root directory for output dataset and metadata.
--metadata-csv: Filename for combined metadata CSV in output root.
--api-key: Google Maps API key (can also be set via GOOGLE_MAPS_API_KEY env var).
--seed: Random seed for reproducible train/valid/test splitting.
--train-ratio: Proportion of samples to use for training set.
--valid-ratio: Proportion of samples to use for validation set.
--headings: Comma-separated list of headings (in degrees) for image capture.
--pitch: Pitch angle for Street View images.
--fov: Field of view for Street View images.
--size: Image size in WIDTHxHEIGHT format, e.g. 640x640.
--radius: Search radius (in meters) for Street View metadata lookup.
--source: Image source for Street View (e.g. "outdoor").
--timeout-seconds: Request timeout in seconds.
--max-retries: Maximum number of retries for failed requests.
--retry-backoff-seconds: Base seconds for exponential backoff between retries.
--min-delay-seconds: Minimum delay between requests to avoid rate limits.
--geocode-delay-seconds: Delay between geocoding requests when postal codes are used.
--metadata-only: If set, only query metadata without downloading images.
```

The script will create a structured output directory containing the extracted images and a combined metadata CSV file. The metadata CSV will include information such as the location ID, postal code, coordinates, image URL, and other relevant details.

### Update_Metadata.py
This source code is responsible for updating the metadata CSV files generated during the dataset extraction process. It can be used to add additional information, correct errors, or modify existing entries in the metadata. This script is particularly useful when you need to remove unwanted images or update the metadata after the initial extraction (usually to prepare for data augmentation).

This script can be skipped if you are not planning to use the data to train a model, as it is primarily intended for preparing the dataset for training.

#### Usage
Basic usage: (For more details, refer to the source code comments or type `python Dataset/Update_Metadata.py --help` for command-line options.)
```
python Dataset/Update_Metadata.py --dataset both
```

The script accepts the following command-line arguments:
```
--dataset: Choice of dataset to update (street, map, or both). Default is "both".
--base-dir: Base directory containing the Dataset folder. Default is the current directory.
--dry-run: If set, the script will run checks and provide a summary without writing any CSV files.
--drop-nonfile-rows: If set, rows with empty paths (non-file rows) will be dropped from the output.
--no-backup: If set, the script will not create backup CSV files before writing updates.
--log-level: Logging level for the script output (DEBUG, INFO, WARNING, ERROR). Default is "INFO".
```

The script will read the existing metadata CSV files, apply the specified updates, and write the updated metadata back to the CSV files. It is recommended to create a backup of the original metadata files before running this script, especially if you are making significant changes.

## Transfer Learning
Transfer learning is a machine learning technique where a pre-trained model is used as a starting point for training on a new dataset. This approach can significantly reduce training time and improve model performance, especially when the new dataset is small or similar to the original dataset. The codebase includes a transfer learning implementation using pytorch's fasterrcnn_resnet50_fpn model. The source code for transfer learning is located in the `Transfer_Learning` directory.

### File Structure:
```
├── Transfer_Learning
|   ├── runs
|   |   ├── run_1
|   |   ├── run_2
|   |   ├── ... more training runs
|   |   └── run_n
|   |       ├── graphical_results
|   |       ├── test_predictions
|   |       ├── model_best.pth
|   |       ├── model_last.pth
|   |       └── train.log
|   └── Transfer_Learning.py
```

The `runs` directory contains the output of the model training process, including trained models, logs, and visualizations. Each training run is stored in a separate subdirectory (e.g., `run_1`, `run_2`, etc.), which contains the following files:
- `graphical_results`: Directory containing visualizations of the model's predictions on the test set
- `test_predictions`: Directory containing the model's predictions on the test set in a structured format
- `model_best.pth`: The best-performing model checkpoint based on validation metrics
- `model_last.pth`: The last model checkpoint saved during training
- `train.log`: Log file containing training progress, metrics, and other relevant information

### Usage:
The `Transfer_Learning.py` script is the main entry point for training the transfer learning model. It includes functions for data loading, model initialization, training, evaluation, and logging. The script can be run from the command line with various options to customize the training process. The full list of command-line arguments and their descriptions can be found in the script's help message, which can be accessed by running:
```
python Transfer_Learning/Transfer_Learning.py --help
```

#### Testing the Model on Unlabelled Images
To test the model on a set of unlabelled images, you can use the `Transfer_Learning.py` script with the appropriate command-line arguments. The script will load the trained model, process the unlabelled images, and generate predictions, which will be saved in the specified output directory.
```
python Transfer_Learning/Transfer_Learning.py --run-name <RUN_NAME> --test-deploy <PATH_TO_UNLABELLED_IMAGES> --deploy-output <OUTPUT_DIRECTORY> --resume <PATH_TO_MODEL_CHECKPOINT> --output-format <OUTPUT_FORMAT>

where:
<RUN_NAME>: Name of the training run to use for testing (e.g., "run_1").
<PATH_TO_UNLABELLED_IMAGES>: Path to the directory containing unlabelled images for testing
<OUTPUT_DIRECTORY>: Path to the directory where the predictions will be saved
<PATH_TO_MODEL_CHECKPOINT>: Path to the model checkpoint file (e.g., "model_best.pth" or "model_last.pth") to resume from
<OUTPUT_FORMAT>: Format for saving predictions (e.g., "json", "csv", "image"). The default format is "image".

Optional command-line arguments:
--score-threshold: Minimum confidence score for predictions to be considered valid (default: 0.5)
```

#### Training the Model
To train the model using transfer learning, you can run the `Transfer_Learning.py` script with the appropriate command-line arguments. The script will load the training and validation and test datasets automatically, initialize the model, and perform the training process. The trained model checkpoints and logs will be saved in the `runs` directory.
```
python Transfer_Learning/Transfer_Learning.py --run-name <RUN_NAME>

where:
<RUN_NAME>: Name of the training run (e.g., "run_1"). This name will be used to create a subdirectory in the `runs` directory for saving the model checkpoints and logs.
```

Optional command-line arguments:
Since there are many command line arguments available for customizing the training process, please refer to the script's help message for a complete list of options:

```
python Transfer_Learning/Transfer_Learning.py --help
```
#### Resuming Training from a Checkpoint
To resume the training process from a specific model checkpoint, you can use the `--resume` argument followed by the path to the checkpoint file. This allows you to continue training from where you left off, which is useful for long training sessions or when experimenting with different hyperparameters.

```
python Transfer_Learning/Transfer_Learning.py --run-name <RUN_NAME> --resume <PATH_TO_MODEL_CHECKPOINT>

where:
<RUN_NAME>: Name of the training run (e.g., "run_1"). This name will be used to create a subdirectory in the `runs` directory for saving the model checkpoints and logs.
<PATH_TO_MODEL_CHECKPOINT>: Path to the model checkpoint file (e.g., "model_best.pth" or "model_last.pth") to resume training from.
```

#### Hyperparameter Findings
This section summarizes the best hyperparameter setting found during the training process. The optimal hyperparameters may vary depending on the specific dataset and task, so it is recommended to experiment with different settings to achieve the best performance. The following hyperparameters were found to yield good results in our experiments for the project:

```
--trainable-backbone-layers: 3
--optimizer: sgd
--learning-rate: 0.0005
--weight-decay: 0.001
--lr-scheduler: cosine
--batch-size: 4
--monitor-metric: map
--early-stopping-patience: 5
```

The other hyperparameters can be left at their default values, as they did not significantly impact the model's performance in our experiments. However, it is always a good idea to perform hyperparameter tuning for your specific use case to achieve the best results.

#### CSV Output Format for Predictions
`Transfer_Learning.py` supports saving the model's predictions in a CSV format. The CSV output will contain the following columns:

```
file_name, xmin, ymin, xmax, ymax, class_label, confidence_score, postal_code

where:
file_name: Name of the image file for which the prediction was made.
xmin, ymin, xmax, ymax: Coordinates of the bounding box for the detected object in the image.
class_label: Predicted class label for the detected object.
confidence_score: Confidence score of the prediction (between 0 and 1).
postal_code: Postal code associated with the image, if available. If not available, this field will be marked as "UNKNOWN".
```
The CSV converter source code can be found in the `COCO_To_CSV` directory. The `coco_to_csv.py` script is responsible for converting COCO JSON annotations to CSV format. You can use this script to convert the model's predictions from COCO format to CSV format for easier analysis and visualization.

##### Important Note
The postal code field in the CSV output follows a specific filename formatting. The filename format is as follows:

```
_XXXXXX_
or
_XXXXXX.

where:
XXXXXX: Represents the 6 digit postal code
```

The following are some valid examples of filenames that contain postal codes:
```
image_123456.jpg
image_123456_SOME_OTHER_TEXT.jpg
image_SOME_OTHER_TEXT_123456.jpg
```

Image filenames that do not contain a valid postal code will have the postal code field marked as "UNKNOWN" in the CSV output. This ensures that the CSV output accurately reflects the presence or absence of postal code information for each image.

## Data Augmentation
Data augmentation is a technique used to artificially increase the size of a dataset by applying various transformations to the existing data. This can help improve the performance of machine learning models by providing them with more diverse training examples. The codebase includes a data augmentation implementation that applies various transformations to the images in the dataset. The source code for data augmentation is located in the `Data_Augmentation` directory.

File Structure:
```
├── Data_Augmentation
|   ├── Result
|   |   ├──Augmented_images         ----------+
|   |   ├── images                            ├── Contains the augmented images generated by the data augmentation process.
|   |   ├── augmented_metadata.csv  ----------+
|   |   └── Check_For_Similar_File.py
|   └── Dataset_Augmentation.py
```

The `Result` directory contains the output of the data augmentation process, including the augmented images and a metadata CSV file. The `augmented_metadata.csv` file contains information about the augmented images, such as the original image filename, the applied transformations, and other relevant details.

### Dataset_Augmentation.py
The main script for data augmentation is `Dataset_Augmentation.py`. This script applies various transformations to the images in the dataset, such as rotation, flipping, scaling, and color adjustments. The augmented images are saved in the `Result/images` directory, and the corresponding metadata is saved in the `augmented_metadata.csv` file.

#### Usage
Basic usage: (For more details, refer to the source code comments or type `python Data_Augmentation/Dataset_Augmentation.py --help` for command-line options.)

```
python Data_Augmentation/Dataset_Augmentation.py --input_metadata <INPUT_DIRECTORY> --output_dir <OUTPUT_DIRECTORY>

where:
<INPUT_DIRECTORY>: Path to the directory containing the original images.
<OUTPUT_DIRECTORY>: Path to the directory where the augmented images will be saved.
```

Command-line arguments:
Since there are many command line arguments available for customizing the data augmentation process, please refer to the script's help message for a complete list of options:

```
python Data_Augmentation/Dataset_Augmentation.py --help
```

### Check_For_Similar_File.py
The `Check_For_Similar_File.py` script is responsible for checking the augmented images for similarity and ensuring that there are no duplicate or near-duplicate images in the dataset. This is important to maintain the quality and diversity of the dataset, as duplicate images can lead to overfitting and reduced model performance.

#### Usage
Basic usage: (For more details, refer to the source code comments or type `python Data_Augmentation/Check_For_Similar_File.py --help` for command-line options.)

```
python Data_Augmentation/Check_For_Similar_File.py --output-dir <OUTPUT_DIRECTORY> --metadata <METADATA_CSV> --image-dir <IMAGE_DIRECTORY>

where:
<OUTPUT_DIRECTORY>: Path to the directory where the results of the similarity check will be saved.
<METADATA_CSV>: Path to the metadata CSV file containing information about the augmented images.
<IMAGE_DIRECTORY>: Path to the directory containing the augmented images to be checked for similarity.
```

Command-line arguments:
Since there are many command line arguments available for customizing the similarity check process, please refer to the script's help message for a complete list of options:

```
python Data_Augmentation/Check_For_Similar_File.py --help
```
